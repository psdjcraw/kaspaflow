# KaspaFlow 직원 결제 처리 플레이북

이 문서는 매장 직원이 KaspaFlow POS에서 결제 상태를 보고 바로 처리하기 위한
간단한 절차다. KaspaFlow는 비수탁형 도구이므로 송금과 환불은 항상 매장 지갑에서
직접 처리한다.

## 기본 원칙

- 고객에게 개인키, 시드 문구, 거래소 로그인 정보를 요청하지 않는다.
- 고객 화면에는 QR, 금액, 주소만 보여준다. 관리자 토큰은 고객에게 보여주지 않는다.
- 결제 상태가 애매하면 KaspaFlow 결제 ID와 매장 지갑 입금 내역을 함께 확인한다.
- 환불은 매장 책임자가 승인한 뒤 매장 지갑에서 직접 송금한다.

## 상태별 처리

### waiting

의미: 아직 입금이 감지되지 않았다.

처리:

1. 고객에게 QR을 다시 스캔하거나 주소/금액을 확인해 달라고 안내한다.
2. 결제 만료 시간이 임박하면 새 결제를 만들 준비를 한다.
3. 고객이 이미 보냈다고 하면 지갑 앱의 tx hash를 요청하고 `상태 확인`을 누른다.

### seen

의미: 체인에서 입금이 감지됐고 확인을 기다리는 중이다.

처리:

1. 고객에게 입금 감지 상태라고 안내한다.
2. 상품 제공 정책이 즉시 제공인지, confirmation 이후 제공인지 매장 정책을 따른다.
3. 오래 머무르면 `상태 확인` 또는 `전체 동기화`를 누른다.

### confirmed

의미: 요청 금액과 맞는 결제가 확인됐다.

처리:

1. 주문을 완료 처리한다.
2. 고객에게 완료 안내를 한다.
3. 영업 종료 시 매출 리포트와 매장 지갑 입금 내역을 대조한다.

### underpaid

의미: 고객이 요청 금액보다 적게 보냈다.

처리:

1. 부족 금액을 고객에게 설명한다.
2. 매장 정책에 따라 추가 송금을 요청하거나 주문을 취소한다.
3. 취소/환불이 필요하면 환불 주소, 사유, tx hash를 결제 상세에 기록한다.
4. 고객이 추가 송금한 경우 `상태 확인`을 누른다.

### overpaid

의미: 고객이 요청 금액보다 많이 보냈다.

처리:

1. 주문은 매장 정책에 따라 완료 처리할 수 있다.
2. 초과분 환불이 필요한지 고객에게 확인한다.
3. 환불이 필요하면 매장 지갑에서 직접 송금하고 환불 tx hash를 기록한다.
4. 환불 기록이 `confirmed` 또는 `rejected`로 검증되는지 확인한다.

### expired

의미: 결제 시간이 지났고 기존 QR을 더 이상 쓰면 안 된다.

처리:

1. 고객에게 새 QR을 만들겠다고 안내한다.
2. 기존 QR을 고객에게 다시 스캔하게 하지 않는다.
3. 고객이 만료 후 송금했다고 주장하면 tx hash와 매장 지갑 입금 내역을 확인한다.
4. 필요하면 새 결제를 만들거나 환불 절차를 따른다.

## 환불 기록

1. 고객 환불 주소를 확인한다.
2. 환불 사유를 짧게 적는다.
3. 매장 지갑에서 직접 KAS를 송금한다.
4. 환불 tx hash를 KaspaFlow 결제 상세에 입력한다.
5. 검증 결과가 `confirmed`인지 확인한다.

## 영업 종료 점검

1. `일일 리포트`를 전송한다.
2. `확인 필요 결제` 큐가 비었는지 확인한다.
3. `openPayments`, `attentionPayments`, `refunds`가 남아 있으면 담당자에게 인계한다.
4. `/api/sales.csv`를 내려받아 보관한다.
5. `npm run backup:data`로 파일 저장소를 백업한다.
